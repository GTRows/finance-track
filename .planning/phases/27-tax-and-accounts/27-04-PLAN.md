<objective>
Ship a CSV statement importer that parses Garanti BBVA, Turkiye Is Bankasi, and Akbank current-account exports behind the existing preview+commit pattern that `ExcelImportService` (Phase 18) already established for the owner xlsx import. Phase 27 closes Track G of the post-v1 backlog; sub-plan 04 (this plan) is `G3` per ROADMAP.md and the LAST plan in Phase 27 — completing it ships the v1.3.0 milestone end-to-end. Each parsed row materialises as one `BudgetTransaction` (`INCOME` or `EXPENSE`) stamped with `account_id` from a user-picked Account entity (the linkage 27-02/27-03 stood up). Bank statements are CSV files with strong locale + format quirks: encoding (Windows-1254 vs UTF-8), delimiter (`;` for Garanti/Akbank Excel TR exports vs `,` for Isbank international format), date format (`dd/MM/yyyy` vs `yyyy-MM-dd`), decimal locale (`,` decimal + `.` thousands vs the inverse), sign convention (separate debit/credit columns vs a single signed amount), header rows (1 line vs metadata block + header), and footer rows (closing balance summary). **Established patterns to mirror (DO NOT improvise — copy these byte-for-byte where applicable):**
- **Preview + commit shape:** The new `BankCsvImportService` exposes `BankCsvImportSummary preview(MultipartFile, Bank, UUID accountId, UUID userId)` and `BankCsvImportSummary commit(MultipartFile, Bank, UUID accountId, UUID userId)`. Mirror the `ExcelImportService.preview / commit` shape verbatim. Preview is `@Transactional(readOnly = true)`. Commit is `@Transactional` (writer scope), publishes `BudgetTransactionPersistedEvent` per row imported, and gets the AFTER_COMMIT rollup for free via the 27-03 `AccountBalanceListener`. The commit's `MultipartFile` is the SAME file the operator previewed — the contract is "preview is advisory; commit recomputes everything from scratch on the canonical file" (matches the existing Excel import — no server-side state between preview and commit).
- **Idempotency / fingerprint:** SHA-256 over the canonical row signature `accountId|isoDate|signedAmountPlain|balanceAfterPlain|counterpartyHash` where `counterpartyHash` is `SHA-256(lowercase-trimmed-description).hex()` truncated to 12 hex chars (60 bits — collision-safe within a single user's import volume). Persist the full SHA-256 hex (64 chars) in the new `transactions.import_fingerprint` column. Pre-load existing fingerprints for the target account at preview/commit start via a batched `txnRepo.findFingerprintsByAccountId(accountId)` and check membership in a `Set<String>` — same `existingFingerprints` shape `ExcelImportService` already uses. The composite-with-account-id is load-bearing: the same row dropped on a different account is intentionally NOT a duplicate (operator might have moved the bank to a different account in the entity).
- **CSV reader contract:** Each `BankCsvParser` exposes `List<RawBankRow> parse(InputStream input, Charset charset, UUID accountId)`. The interface contract: input is the raw upload stream; charset is bank-specific (resolved by the registry from the `Bank` enum); the parser returns a list of `RawBankRow(int rowNumber, LocalDate date, BigDecimal signedAmount, BigDecimal balanceAfter, String counterparty, String description, String warning)`. Parser-level warnings are per-row strings ("Unparseable date", "Missing amount", "Both debit and credit columns populated"); the `warning != null` rows skip commit but still surface in preview so the operator can see them. The service layer NEVER throws on a single bad row — only the file-level read fails (encoding error, malformed bank format detected by header sniff) raise `BusinessRuleException("Invalid CSV", "BANK_CSV_INVALID")` which lands as 400 via the existing `GlobalExceptionHandler`.
- **Bank-specific format hints (best-effort — flag uncertainty in the parser tests, the executor verifies against real fixtures):**
  - **Garanti BBVA (`GARANTI`)**: Encoding Windows-1254 (Excel TR locale default; the export option labelled "CSV (Windows)" produces this). Delimiter `;`. Date `dd/MM/yyyy`. Decimal `,` (e.g. `1.234,56`). Sign convention: SINGLE column `Tutar` with negative for debit. Header at row 1 (no metadata block). Possible footer rows for "Sayfa Sonu Bakiye" — ignore lines that do not parse to (date, amount).
  - **Turkiye Is Bankasi (`ISBANK`)**: Encoding UTF-8 (modern Internet Bank CSV). Delimiter `,` (international format) — but if a `;` is detected at a far higher count than `,` in the first 5 lines, fall back to `;`. Date `yyyy-MM-dd`. Decimal `.` for the international format / `,` for the legacy format — the parser sniffs by counting `,`-as-thousand candidates in the first numeric column. Sign convention: TWO columns `Borc` (debit) + `Alacak` (credit) — exactly one populated per row. Header at row 1. Possible 2-line metadata header before the column header — sniff for the first line that contains `Tarih` (date) and `Aciklama` (description).
  - **Akbank (`AKBANK`)**: Encoding Windows-1254. Delimiter `;`. Date `dd.MM.yyyy`. Decimal `,`. Sign convention: SINGLE column `Tutar` with `-` prefix for debit. Possible 5-line metadata block before the header (account holder, IBAN, period, etc.) — skip until a line containing `Tarih`. Footer "Toplam Borc" / "Toplam Alacak" rows — ignore.
  - These are PLAUSIBLE schemas based on publicly described exports; the executor will adjust against actual fixture files. The parser tests live under `backend/src/test/resources/bank-csv/` with named fixtures (`garanti-2025-01.csv`, `isbank-international-2025-01.csv`, `isbank-legacy-2025-01.csv`, `akbank-2025-01.csv`); the executor authors them by sketching the schema from the parser code, then running the parser test, then adjusting if the real export differs (operator can replace any fixture with a sanitized real export and the test re-runs against it).
- **Auto-categorisation:** Reuse `TransactionCategoryRuleRepository.findByUserIdOrderByPriorityAsc(userId)` — load the user's rules once at the start of preview/commit, walk in priority order, first match wins. Rule pattern is regex (the existing engine — `TransactionCategoryRuleService` already does this in the budget recurring-transaction flow). **Constraining decisions:**
- **Three concrete parsers + one interface, NO format-detection auto-selection.** The operator picks the bank explicitly via radio. Auto-detection by sniffing the file header is a future enhancement (would need a confidence-scored format identifier to avoid mis-classification); the explicit picker is the simplest correct path. Documented in "Decisions Made".
- **One bank per file.** A mixed file (one row from Garanti, one from Akbank — a hypothetical aggregated export) is NOT supported. Each upload is a single-bank file. The parser sniffs the bank's header signature on line ~1 and rejects with `BusinessRuleException("CSV does not match the selected bank", "BANK_CSV_FORMAT_MISMATCH")` if the file is from a different bank than the picker says.
- **Idempotent on re-upload.** Re-uploading the same file is a no-op: every row's fingerprint is already in `existingFingerprints` and the commit's `imported = 0, duplicates = N`. The fingerprint is per-account, so the same file dropped on Account A then Account B intentionally double-imports (this is correct — the operator might have re-classified the bank, or might have a sandbox account they are migrating to a real one).
- **Best-effort categorisation, never fail-closed.** Rules engine NEVER blocks an import. If the regex throws (malformed user-supplied pattern), catch + log + continue with `categoryId = null`. The operator categorises post-import via the existing budget UI. Documented in "Decisions Made".
- **Currency is the account's currency.** Each `Account` has a fixed `currency` (set at create-time per 27-02). The CSV import stamps the row's `currency` from `account.getCurrency()` and the row's `amount` field carries the parser's signed amount (already in account currency — the bank statement is by definition in the bank's currency). Cross-currency imports (a row in EUR on a TRY account because of a SWIFT inflow) are flagged with a per-row warning; the row imports at face-value with the account's currency stamped, the operator reconciles manually if the rate matters. Documented in "Decisions Made". The 27-03 emergency-fund tile already documents the same face-value cross-currency limitation.
- **`originalAmount` / `originalCurrency` on `BudgetTransaction` (V30 multi-currency columns) are populated when the parser detects an inline currency code on the description.** Most TR bank rows are TRY-only and these columns stay null. Garanti's "EFT GIDEN" rows occasionally embed `(USD 50.00)` in the description; the parser's heuristic regex pulls the amount + currency code into `originalAmount` / `originalCurrency`. Best-effort, documented as a per-row warning if the regex matches but cannot parse the number.
- **`@TransactionalEventListener(AFTER_COMMIT)` at the existing 27-03 listener does the rollup.** This plan publishes `BudgetTransactionPersistedEvent` PER imported row (NOT one batch event). The listener already debounces nothing — every row is an independent commit-then-rollup. For a 200-row import this is 200 listener invocations, each a `REQUIRES_NEW` short transaction; the `AccountBalanceUpdater` is sub-millisecond per call. If profiling shows this is hot (it should not be — the operator imports monthly), Phase 30 owns the optimisation.
- **NO new endpoint for "list past imports".** History is auditable via `audit_log` (the 24-08 contract); a per-import history view is a future enhancement that would need a separate `import_runs` table. Out of scope. Documented in "Deferred Enhancements".
- **NO support for credit-card statement CSVs.** Garanti / Isbank / Akbank credit cards have a different export shape (statement period, minimum payment, etc.) than current accounts. This plan ships current-account CSV only. The credit-card variant is a follow-up plan in a future phase. Documented in "Deferred Enhancements".
- **NO recurrence detection.** A rent payment that appears every month is NOT auto-flagged as recurring. The existing recurring-template flow (`RecurringTemplateService`) is operator-initiated; importing a row does not synthesise a template. Documented in "Deferred Enhancements".
- **NO retroactive backfill into `ExcelImportService`.** The Excel importer at `/settings/import` does NOT gain a fingerprint column write — it is a one-time owner-history migration with its own dedupe strategy (the existing `[xlsx-import]` notes prefix). Both flows write `BudgetTransaction` rows but only the CSV path stamps `import_fingerprint`. Mixed: an owner who imported via Excel and later imports the same data via CSV would re-import (the Excel rows have no fingerprint to match against). This is acceptable — the Excel migration is a one-time operation; the CSV flow is the ongoing operational path.
- **Rollback boundary:** `git revert` of this plan's commits + drop the `import_fingerprint` column via a fresh migration (Flyway Community has no `undo`; standard pattern documented in `docs/OPERATIONS.md` for this project). Match the 27-02 / 27-03 precedent of describing rollback in the SUMMARY's "Deferred Enhancements" section.
- **OpenAPI spec regen is best-effort.** Per 27-01 / 27-02 / 27-03 precedent, `scripts/regen-openapi.sh` fails on a pre-existing 26-01 OpenTelemetry classpath issue. Task 6 verify attempts the regen; if it fails, document under "Deviations from Plan" with the same disclaimer 27-03 used and rely on the new WebMvc tests for endpoint coverage.

               Resolver(List<TransactionCategoryRule> rules) {
                   this.compiled = new java.util.ArrayList<>(rules.size());
                   for (TransactionCategoryRule r : rules) {
                       try {
                           Pattern p =

                       if (cr.pattern().matcher(lower).find()) {
                           return cr.categoryId();
                       }
                   }
                   return null;
               }

           @Transactional(readOnly = true)
           public BankCsvImportSummary preview(
                   MultipartFile file, Bank bank, UUID accountId, UUID userId) {
               return run(file, bank, accountId, userId, false);
           }

           @Transactional
           public BankCsvImportSummary commit(
                   MultipartFile file, Bank bank, UUID accountId, UUID userId) {
               return run(file, bank, accountId, userId, true);
           }

           private BankCsvImportSummary run(
                   MultipartFile file,
                   Bank bank,
                   UUID accountId,
                   UUID userId,
                   boolean commit) {
               Account account = requireOwnedAccount(accountId, userId);
               BankCsvParser parser = parserRegistry.get(bank);
               List<RawBankRow> raw;
               try (InputStream is = file.getInputStream()) {
                   raw = parser.parse(is);
               } catch (IllegalArgumentException | IOException e) {
                   auditService.failure(
                           AuditAction.BANK_CSV_FAILED,
                           userId,
                           currentUsername(),
                           "bank=" + bank + " account=" + accountId + " err=" + e.getMessage());
                   throw new BusinessRuleException(
                           "Invalid CSV: " + e.getMessage(), "BANK_CSV_INVALID");
               }
               BankCsvCategoryMatcher.Resolver resolver = categoryMatcher.resolverFor(userId);
               Set<String> existing = transactionRepository.findFingerprintsByAccountId(accountId);
               Map<UUID, String> categoryNames = loadCategoryNames(userId);

               List<BankCsvPreviewRow> rows = new ArrayList<>();
               int imported = 0;
               int skipped = 0;
               int duplicates = 0;
               int warnings = 0;

               for (RawBankRow rr : raw) {
                   String warning = rr.warning();
                   BigDecimal signed = rr.signedAmount();
                   BudgetTransaction.TxnType type = null;
                   BigDecimal amount = null;
                   String fingerprint = null;
                   boolean duplicate = false;
                   UUID matchedCat = null;
                   if (warning == null && (signed == null || rr.date() == null)) {
                       warning = "Missing date or amount";
                   }
                   if (warning == null) {
                       type =
                               signed.signum() >= 0
                                       ? BudgetTransaction.TxnType.INCOME
                                       : BudgetTransaction.TxnType.EXPENSE;
                       amount = signed.abs();
                       fingerprint =
                               fingerprint(accountId, rr.date(), signed, rr.balanceAfter(), rr.description());
                       duplicate = existing.contains(fingerprint);
                       matchedCat = resolver.resolve(rr.description());
                   }
                   if (warning != null) warnings++;
                   if (duplicate) duplicates++;
                   String catName =
                           matchedCat != null ? categoryNames.get(matchedCat) : null;

                   BankCsvPreviewRow previewRow =
                           new BankCsvPreviewRow(
                                   rr.rowNumber(),
                                   rr.date(),
                                   type,
                                   amount,
                                   rr.description(),
                                   rr.counterparty(),
                                   matchedCat,
                                   catName,
                                   fingerprint,
                                   warning,
                                   duplicate);
                   rows.add(previewRow);

                   if (!commit || warning != null || duplicate || amount == null) {
                       if (commit && (warning != null || duplicate)) skipped++;
                       continue;
                   }

                   BudgetTransaction txn =
                           BudgetTransaction.builder()
                                   .userId(userId)
                                   .accountId(accountId)
                                   .txnType(type)
                                   .amount(amount)
                                   .currency(account.getCurrency())
                                   .categoryId(matchedCat)
                                   .description(rr.description())
                                   .txnDate(rr.date())
                                   .importFingerprint(fingerprint)
                                   .build();
                   try {
                       BudgetTransaction saved = transactionRepository.save(txn);
                       existing.add(fingerprint); // local dedupe within this commit
                       events.publishEvent(
                               new BudgetTransactionPersistedEvent(
                                       userId,
                                       saved.getId(),
                                       saved.getTxnType(),
                                       saved.getCategoryId(),
                                       saved.getAmount(),
                                       saved.getTxnDate(),
                                       accountId,
                                       null /* previousAccountId */));
                       imported++;
                   } catch (DataIntegrityViolationException dup) {
                       // Race lost to a concurrent commit on the same fingerprint.
                       skipped++;
                       duplicates++;
                       log.debug(
                               "Bank CSV row skipped on race-lost dedupe: fingerprint={}",
                               fingerprint);
                   }
               }

               BankCsvImportSummary summary =
                       new BankCsvImportSummary(
                               rows.size(), imported, skipped, duplicates, warnings, rows);

               String detail =
                       String.format(
                               Locale.ROOT,
                               "bank=%s account=%s rows=%d imported=%d skipped=%d duplicates=%d warnings=%d",
                               bank,
                               accountId,
                               summary.totalRows(),
                               summary.importedRows(),
                               summary.skippedRows(),
                               summary.duplicateRows(),
                               summary.warningRows());
               auditService.success(
                       commit ? AuditAction.BANK_CSV_COMMITTED : AuditAction.BANK_CSV_PREVIEWED,
                       userId,
                       currentUsername(),
                       detail);
               return summary;
           }

           private Account requireOwnedAccount(UUID accountId, UUID userId) {
               return accountRepository
                       .findByIdAndUserIdAndArchivedFalse(accountId, userId)
                       .orElseThrow(
                               () -> {
                                   auditService.failure(
                                           AuditAction.BANK_CSV_FAILED,
                                           userId,
                                           currentUsername(),
                                           "ACCOUNT_NOT_OWNED accountId=" + accountId);
                                   return new BusinessRuleException(
                                           "Account not found", "ACCOUNT_NOT_OWNED");
                               });
           }

           private Map<UUID, String> loadCategoryNames(UUID userId) {
               Map<UUID, String> map = new HashMap<>();
               expenseRepo
                       .findByUserIdOrderByNameAsc(userId)
                       .forEach(c -> map.put(c.getId(), c.getName()));
               incomeRepo
                       .findByUserIdOrderByNameAsc(userId)
                       .forEach(c -> map.put(c.getId(), c.getName()));
               return map;
           }

           static String fingerprint(
                   UUID accountId,
                   LocalDate date,
                   BigDecimal signedAmount,
                   BigDecimal balanceAfter,
                   String description) {
               try {
                   MessageDigest md = MessageDigest.getInstance("SHA-256");
                   StringBuilder seed = new StringBuilder(128);
                   seed.append(accountId);
                   seed.append('|');
                   seed.append(date == null ? "" : date.toString());
                   seed.append('|');
                   seed.append(
                           signedAmount == null
                                   ? ""
                                   : signedAmount.stripTrailingZeros().toPlainString());
                   seed.append('|');
                   seed.append(
                           balanceAfter == null
                                   ? ""
                                   : balanceAfter.stripTrailingZeros().toPlainString());
                   seed.append('|');
                   String desc =
                           description == null ? "" : description.toLowerCase(Locale.ROOT).trim();
                   seed.append(desc);
                   byte[] digest = md.digest(seed.toString().getBytes(StandardCharsets.UTF_8));
                   StringBuilder hex = new StringBuilder(64);
                   for (byte b : digest) hex.append(String.format("%02x", b));
                   return hex.toString();
               } catch (NoSuchAlgorithmException e) {
                   throw new IllegalStateException("SHA-256 unavailable", e);
               }
           }

           private static String currentUsername() {
               Authentication auth = SecurityContextHolder.getContext().getAuthentication();
               return auth != null ? auth.getName() : null;
           }
       }
