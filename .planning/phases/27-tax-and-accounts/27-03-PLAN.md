<objective>
Wire every transaction-bearing entity (`investment_transactions`, `transactions` (budget), `bill_payments`) to the standalone `accounts` entity that 27-02 stood up, and ship an emergency-fund coverage tile on the dashboard that rolls off `accounts.current_balance` filtered by account type. Phase 27 closes Track G of the post-v1 backlog; sub-plan 03 (this plan) is `G2-b` per ROADMAP.md and the second half of the G2 pair started in 27-02 (sha pending — see STATE.md). The wiring is **opt-in and nullable**: every existing row stays at `account_id IS NULL` (a "no account" sentinel that means "out-of-band — does not move any account balance"). The owner attaches an `account_id` going forward via the create/edit form's new optional dropdown. When a transaction with a non-null `account_id` is inserted/updated/deleted, the matching `Account.currentBalance` is recomputed via a `@TransactionalEventListener(AFTER_COMMIT)` listener — the persistence path stays lean, the listener owns the rollup. The emergency-fund tile reads the same `accounts` aggregate, scoped to types the user has flagged as part of their emergency reserve (default `[BANK_SAVINGS]`, with optional inclusion of `BANK_CHECKING` and `CASH` per a tri-state user-settings toggle), and divides by the trailing 12-month average expense (already produced by `FireService.averagesFromTransactions(...)`) to surface "X.X months covered" with the threshold band red < 3 / amber 3-6 / green > 6.

**Constraining decisions:**
- **Nullable FK + null-as-out-of-band semantics.** The new `account_id` columns are nullable and existing rows backfill to NULL. The aggregator skips null-account events. The plan ships **zero auto-assignment** of historical rows. Documented in "Decisions Made". The owner can attach an account via the edit form per row, or leave the historical book as-is.
- **`@TransactionalEventListener(phase = AFTER_COMMIT)` over a synchronous in-transaction update.** A synchronous update would tie the balance write to the writer's transaction — a balance constraint failure would roll the transaction creation back, which is the wrong UX (a typo in `currentBalance` precision should not block recording the transaction). The 25-01 listener pattern already encodes this trade-off (see `HoldingProjectionListener.onTransactionRecorded` body: catches `BusinessRuleException` and logs without rethrowing). Reuse it.
- **`REQUIRES_NEW` propagation on the listener's write transaction.** The writer's transaction has already committed when the listener fires. Without `REQUIRES_NEW`, a `@Transactional` method called from the listener body would surprise-attach to whatever ambient transaction is running (e.g. a test fixture's outer transaction) and make the rollup invisible until that fixture commits — flaky test fingerprint. `REQUIRES_NEW` makes the write a hard commit boundary.
- **Listener does NOT validate ownership before applying the delta.** The writer's `@AuthenticationPrincipal`-scoped service has already enforced that the user owns both the transaction-bearing row AND the picked `Account` (new validation in the service layer — see Task 3). Re-validating at the listener is duplicate work and creates a race window if the operator archives the account between the writer's commit and the listener's read.
- **Service-layer ownership check on `accountId`.** When the `accountId` is non-null, the service MUST call `accountRepository.findByIdAndUserIdAndArchivedFalse(accountId, userId)` and `BusinessRuleException("Account not found", "ACCOUNT_NOT_OWNED")` if absent (audit failure first, throw second — 24-08 pattern). This is the load-bearing guard against attaching transactions to a foreign user's account.
- **Investment-transaction account semantics.** A BUY moves cash OUT of the picked account (the brokerage cash account or a bank account funding the buy). A SELL moves cash IN. A DEPOSIT is brokerage funding inflow (`+amountTry`). A WITHDRAW is outflow (`-amountTry`). A BES_CONTRIBUTION mirrors BUY (cash leaves the source account into the BES wrapper). A REBALANCE is intra-portfolio and zeroes out (`0`) at the cash-account level — it does not move bank money. The aggregator encodes this; tests pin every branch.
- **Budget transaction account semantics.** INCOME → `+amount` to picked account. EXPENSE → `-amount`. The currency on the transaction is informational (the `amount` is already in the user's home currency per `BudgetService.convertForUser` — V11 / V20 history). The plan does NOT cross-check transaction currency against `Account.currency`: the operator may legitimately pay a TRY-denominated bill from a USD account at the bank's blended rate — true cross-currency would need a per-transaction FX rate which is out of scope here. Documented in "Decisions Made".
- **BillPayment account semantics.** Marking a bill PAID → `-amount` from the picked account. PAID→PENDING reversal → `+amount`. PAID→SKIPPED also reverses (operator changed their mind; `+amount`). The aggregator's tri-state `from`/`to` shape covers this. The bill itself does not own an account (the picked account belongs to the **payment** row, not the bill template) so an operator can pay one bill from different accounts month-to-month without losing history.
- **Emergency-fund inclusion types: tri-state.** `BANK_SAVINGS` is always-on (the canonical "savings reserve" type). `BANK_CHECKING` and `CASH` are user-toggleable. `BROKERAGE_CASH`, `CRYPTO_WALLET`, `OTHER` are NEVER included — they have liquidity profile mismatches (broker cash sits behind a 1-3 day settlement, crypto is volatile, OTHER is a catch-all). Documented in "Decisions Made". An advanced operator who disagrees can still surface their own number from the `/accounts` page totals strip; this is the dashboard's opinionated default.
- **Coverage = `currentReserve / monthlyAverageExpense`.** Reuse `FireService.averagesFromTransactions(...)` shape — but extracted into a shared `BudgetAveragesService` so `FireService` and `EmergencyFundService` share the trailing-12-month walker without duplicating the SAMPLE_MONTHS / MIN_SAMPLES constants. If the user has fewer than 3 expense samples, `monthsCovered` is null and `status = "insufficient-data"` (the tile shows a "need more expense history" copy block). When monthly average is zero (never spent anything), `monthsCovered = 999` (sentinel for "infinity") and `status = "green"`.
- **Single-currency reserve in 27-03.** The `currentReserve` rolls up `Account.currentBalance` across the included accounts at face value, NOT FX-converted. A USD savings account with 1,000 USD adds 1,000 to the rollup — the tile copy says "across all included currencies; cross-currency conversion ships in 28-01" so the operator understands the limitation. The `buckets` field in the response gives per-currency breakdown so the frontend can display the slice if it wants. Mirrors the 27-02 stat-strip decision. The threshold colour bands apply to `monthsCovered` computed against the user's home currency expenses; if the savings sit in USD the operator gets an over-stated coverage number — flagged in "Deferred Enhancements" and called out in the tile's footer copy.
- **No new audit constants.** `accountId=...` is appended to existing audit detail strings. Adding `*_LINKED_TO_ACCOUNT` constants would balloon the table for no operator-actionable signal.
- **No `@Observed` on the listener.** The 26-01 servlet observation handler covers HTTP boundaries; the listener is in-process. The micrometer-tracing bridge produces a span automatically for `@TransactionalEventListener` invocations under the autoconfigure default; explicit `@Observed` is reserved for hot batch paths (per 27-02's precedent).
- **No frontend chart for emergency-fund history.** Trend over time would need a daily-snapshot worker à la `SnapshotScheduler` — explicitly deferred to 28-01 per ROADMAP.
- **No backfill script.** Existing rows stay null. The owner attaches accounts going forward. Documented in "Decisions Made".
- **Rollback boundary:** `git revert` of this plan's commits + `flyway:undo` of V42 + V43 (Flyway Community does not support `undo`, so the rollback path is "drop column" followed by a fresh migration; documented in `docs/OPERATIONS.md` as the standard rollback procedure for this project — match the 27-02 precedent of describing rollback in the SUMMARY's "Deferred Enhancements" section, NOT as a runbook).
- **OpenAPI spec regen is best-effort.** Per 27-01 / 27-02 precedent, `scripts/regen-openapi.sh` fails on a pre-existing 26-01 OpenTelemetry classpath issue. Task 6 verify attempts the regen; if it fails, document under "Deviations from Plan" with the same disclaimer 27-02 used and rely on the new WebMvc tests for endpoint coverage.

       ```java
       package com.fintrack.account;

       import com.fintrack.common.entity.BillPayment;
       import com.fintrack.common.entity.BudgetTransaction;
       import com.fintrack.common.entity.InvestmentTransaction;
       import java.math.BigDecimal;

       /**
        * Pure helpers that compute signed deltas to apply against
        * {@code Account.currentBalance} when a transaction-bearing row is
        * inserted, updated, or deleted. The {@code AccountBalanceListener}
        * consumes these deltas after the writer commits.
        */
       public final class AccountTransactionAggregator {

           private AccountTransactionAggregator() {}

           /**
            * Budget transaction net delta against the linked account.
            * INCOME → +amount, EXPENSE → -amount. Amount is in the user's
            * home currency (BudgetService converts at write time).
            */
           public static BigDecimal budgetDelta(
                   BudgetTransaction.TxnType txnType, BigDecimal amount) {
               if (amount == null) return BigDecimal.ZERO;
               return txnType == BudgetTransaction.TxnType.INCOME ? amount : amount.negate();
           }

           /**
            * Investment transaction net delta against the linked cash/bank account.
            * BUY / BES_CONTRIBUTION → -(amountTry) (amountTry already includes fee),
            * SELL → +amountTry (amountTry already nets fee per InvestmentTransactionService.record),
            * DEPOSIT → +amountTry, WITHDRAW → -amountTry,
            * REBALANCE → 0 (intra-portfolio reshuffle, no cash movement at this level).
            */
           public static BigDecimal investmentDelta(
                   InvestmentTransaction.TxnType txnType, BigDecimal amountTry) {
               if (amountTry == null) return BigDecimal.ZERO;
               return switch (txnType) {
                   case BUY, BES_CONTRIBUTION, WITHDRAW -> amountTry.negate();
                   case SELL, DEPOSIT -> amountTry;
                   case REBALANCE -> BigDecimal.ZERO;
               };
           }

           /**
            * Bill payment delta. A PENDING→PAID transition moves -amount;
            * PAID→PENDING reverses (+amount); PAID→SKIPPED reverses (+amount);
            * any other transition is a no-op (returns zero). Used by the listener
            * when a BillPaid event is replayed with a status change.
            */
           public static BigDecimal billPaymentDelta(
                   BillPayment.PaymentStatus from,
                   BillPayment.PaymentStatus to,
                   BigDecimal amount) {
               if (amount == null) return BigDecimal.ZERO;
               if (from == to) return BigDecimal.ZERO;
               // Forward path: pending/skipped -> paid moves -amount.
               if (to == BillPayment.PaymentStatus.PAID) return amount.negate();
               // Reversal path: paid -> pending/skipped moves +amount.
               if (from == BillPayment.PaymentStatus.PAID) return amount;
               return BigDecimal.ZERO;
           }
       }
       ```

       ```java
       import com.fintrack.common.entity.Account;

       import java.util.UUID;

       import lombok.extern.slf4j.Slf4j;

        * Applies a signed delta to {@link Account#getCurrentBalance()} in its own
        * short transaction (REQUIRES_NEW). Called from {@link AccountBalanceListener}
        * after the writer's transaction has already committed. A missing account row
        * (operator hard-deleted between the writer's commit and the listener's read)
        * is logged at WARN and silently skipped — the FK is ON DELETE SET NULL so
        * the transaction row already lost its account_id link.
        */
       @Component
       @RequiredArgsConstructor
       @Slf4j
       public class AccountBalanceUpdater {

           private final AccountRepository accountRepository;

           @Transactional(propagation = Propagation.REQUIRES_NEW)
           public void apply(UUID accountId, BigDecimal delta) {
               if (accountId == null || delta == null || delta.signum() == 0) {
                   return;
               }
               Account account = accountRepository.findById(accountId).orElse(null);
               if (account == null) {
                   log.warn(
                           "Account balance rollup skipped: account row not found accountId={}",
                           accountId);
                   return;
               }
               BigDecimal current =
                       account.getCurrentBalance() != null
                               ? account.getCurrentBalance()
                               : BigDecimal.ZERO;
               account.setCurrentBalance(current.add(delta));
               accountRepository.save(account);
               log.debug(
                       "Account balance updated: accountId={} delta={} newBalance={}",
                       accountId,
                       delta,
                       account.getCurrentBalance());
           }
       }
       ```

       ```java
       import com.fintrack.account.AccountRepository;
       import com.fintrack.budget.TransactionRepository;
       import com.fintrack.common.entity.Account;
       import com.fintrack.common.entity.BudgetTransaction;
       import com.fintrack.common.entity.UserSettings;
       import com.fintrack.dashboard.dto.EmergencyFundResponse;
       import com.fintrack.dashboard.dto.EmergencyFundResponse.CurrencyBucket;
       import com.fintrack.settings.UserSettingsRepository;
       import java.math.BigDecimal;
       import java.math.RoundingMode;
       import java.time.LocalDate;
       import java.time.YearMonth;
       import java.util.*;
       import lombok.RequiredArgsConstructor;
       import lombok.extern.slf4j.Slf4j;
       import org.springframework.stereotype.Service;
       import org.springframework.transaction.annotation.Transactional;

       @Service
       @RequiredArgsConstructor
       @Slf4j
       public class EmergencyFundService {

           private static final int SAMPLE_MONTHS = 12;
           private static final int MIN_SAMPLES = 3;
           private static final BigDecimal RED_BAND = new BigDecimal("3");
           private static final BigDecimal AMBER_BAND = new BigDecimal("6");
           private static final List<Account.AccountType> DEFAULT_INCLUDED =
                   List.of(Account.AccountType.BANK_SAVINGS);
           private static final BigDecimal SENTINEL_INFINITE = new BigDecimal("999");

           private final AccountRepository accountRepository;
           private final TransactionRepository txnRepo;
           private final UserSettingsRepository userSettingsRepo;

           @Transactional(readOnly = true)
           public EmergencyFundResponse compute(UUID userId) {
               List<Account.AccountType> includedTypes = resolveIncludedTypes(userId);
               List<CurrencyBucket> buckets =
                       accountRepository.sumBalancesByTypeForUser(userId, includedTypes).stream()
                               .map(row -> new CurrencyBucket((String) row[0], (BigDecimal) row[1]))
                               .toList();

               BigDecimal currentReserve =
                       buckets.stream()
                               .map(CurrencyBucket::totalBalance)
                               .reduce(BigDecimal.ZERO, BigDecimal::add);

               // Monthly expense rolling average — same shape as FireService.averagesFromTransactions.
               YearMonth current = YearMonth.now();
               BigDecimal expenseSum = BigDecimal.ZERO;
               int samples = 0;
               for (int i = 0; i < SAMPLE_MONTHS; i++) {
                   YearMonth ym = current.minusMonths(i);
                   LocalDate from = ym.atDay(1);
                   LocalDate to = ym.atEndOfMonth();
                   BigDecimal exp =
                           nvl(
                                   txnRepo.sumByUserIdAndTypeAndDateRange(
                                           userId, BudgetTransaction.TxnType.EXPENSE, from, to));
                   if (exp.signum() == 0) continue;
                   expenseSum = expenseSum.add(exp);
                   samples++;
               }
               BigDecimal monthlyAverageExpense =
                       samples > 0
                               ? expenseSum.divide(
                                       BigDecimal.valueOf(samples), 2, RoundingMode.HALF_UP)
                               : BigDecimal.ZERO;

               BigDecimal monthsCovered;
               String status;
               if (samples < MIN_SAMPLES) {
                   monthsCovered = null;
                   status = "insufficient-data";
               } else if (monthlyAverageExpense.signum() == 0) {
                   monthsCovered = SENTINEL_INFINITE;
                   status = "green";
               } else {
                   monthsCovered =
                           currentReserve.divide(monthlyAverageExpense, 1, RoundingMode.HALF_UP);
                   if (monthsCovered.compareTo(RED_BAND) < 0) status = "red";
                   else if (monthsCovered.compareTo(AMBER_BAND) <= 0) status = "amber";
                   else status = "green";
               }

               return new EmergencyFundResponse(
                       currentReserve,
                       buckets,
                       monthlyAverageExpense,
                       monthsCovered,
                       status,
                       includedTypes,
                       samples);
           }

           private List<Account.AccountType> resolveIncludedTypes(UUID userId) {
               UserSettings settings = userSettingsRepo.findById(userId).orElse(null);
               if (settings == null || settings.getEmergencyFundIncludeTypes() == null
                       || settings.getEmergencyFundIncludeTypes().isEmpty()) {
                   return DEFAULT_INCLUDED;
               }
               List<Account.AccountType> out = new ArrayList<>();
               for (String name : settings.getEmergencyFundIncludeTypes()) {
                   try {
                       out.add(Account.AccountType.valueOf(name));
                   } catch (IllegalArgumentException ex) {
                       log.warn(
                               "Unknown emergency-fund account type ignored: userId={} value={}",
                               userId,
                               name);
                   }
               }
               // BANK_SAVINGS is always-on — defensively re-add if a corrupted settings row dropped it.
               if (!out.contains(Account.AccountType.BANK_SAVINGS)) {
                   out.add(0, Account.AccountType.BANK_SAVINGS);
               }
               return out;
           }

           private static BigDecimal nvl(BigDecimal v) {
               return v != null ? v : BigDecimal.ZERO;
           }
       }
       ```
