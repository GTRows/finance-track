<objective>
Wire OWASP Dependency Check into CI as an opt-in gate that fails on new CRITICAL CVEs, and harden the production Spring profile to refuse to boot when CORS, Redis password, JWT secret, or the receipt-signing secret are missing or insecure.

Purpose: D9 closes the supply-chain blind spot — Trivy scans containers but does not enumerate transitive Java dependency CVEs from the Maven dependency tree. Production fail-fast removes the most common source of accidental misconfiguration: a hot-reload of `application.yml` or a missing env var silently leaving CORS open, Redis unauthenticated, or the receipt-signing secret at its dev default.
Output: `org.owasp:dependency-check-maven` plugin under an opt-in `security` Maven profile with `failBuildOnCVSS=9.0` (CRITICAL only) and a curated suppression file; new CI job `dependency-check` gated on `pom.xml` changes; `ProductionProfileGuard` `@Component @Profile("production")` runs at startup and validates CORS allow-list, Redis password, JWT secret, and `RECEIPT_SIGNING_SECRET` are non-default; `SecurityConfig.corsConfigurationSource()` binds to `CORS_ALLOWED_ORIGINS` with the wildcard fallback only outside production; updated `.env.example` and `docs/SECURITY.md`.
</objective>

  <files>backend/pom.xml, backend/owasp-suppressions.xml, .github/workflows/ci.yml</files>
  <action>
    1. `backend/pom.xml` — add a new `<profile>` named `security` (sibling to the existing `mutation` profile from plan 23-02) with `<build><plugins>` containing:
       ```xml
       <plugin>
         <groupId>org.owasp</groupId>
         <artifactId>dependency-check-maven</artifactId>
         <version>11.1.1</version>
         <configuration>
           <failBuildOnCVSS>9.0</failBuildOnCVSS>
           <suppressionFiles>
             <suppressionFile>owasp-suppressions.xml</suppressionFile>
           </suppressionFiles>
           <formats>
             <format>HTML</format>
             <format>SARIF</format>
           </formats>
           <nvdApiKey>${env.NVD_API_KEY}</nvdApiKey>
           <nvdApiDelay>2000</nvdApiDelay>
           <nvdValidForHours>24</nvdValidForHours>
           <skipProvidedScope>false</skipProvidedScope>
           <skipRuntimeScope>false</skipRuntimeScope>
           <skipTestScope>true</skipTestScope>
         </configuration>
       </plugin>
       ```
       Note `failBuildOnCVSS=9.0` triggers ONLY on CRITICAL (CVSS >= 9.0); HIGH/MEDIUM are reported but do not break CI — keeps the gate signal-rich. Suppression file is required even if empty so the plugin does not warn about missing config.
    2. `backend/owasp-suppressions.xml` — create with empty `<suppressions xmlns="https://jeremylong.github.io/DependencyCheck/dependency-suppression.1.3.xsd"></suppressions>` skeleton and a leading comment explaining: "Add `<suppress>` blocks here for known-acceptable CVEs with CVSS >= 9.0.     3. `.github/workflows/ci.yml` — add a new top-level job `dependency-check` modelled on the `mutation` job:
       ```yaml
         dependency-check:
           name: OWASP Dependency Check (CRITICAL gate)
           runs-on: ubuntu-latest
           needs: backend
           timeout-minutes: 25
           defaults:
             run:
               working-directory: backend
           steps:
             - uses: actions/checkout@v6
               with: { fetch-depth: 2 }
             - name: Detect dependency changes
               id: filter
               uses: dorny/paths-filter@v3
               with:
                 filters: |
                   deps:
                     - 'backend/pom.xml'
                     - 'backend/owasp-suppressions.xml'
             - name: Set up JDK 21
               if: steps.filter.outputs.deps == 'true'
               uses: actions/setup-java@v5
               with: { distribution: temurin, java-version: "21", cache: maven }
             - name: Make mvnw executable
               if: steps.filter.outputs.deps == 'true'
               run: chmod +x mvnw
             - name: Run dependency check
               if: steps.filter.outputs.deps == 'true'
               env:
                 NVD_API_KEY: ${{ secrets.NVD_API_KEY }}
               run: ./mvnw -B -ntp -P security org.owasp:dependency-check-maven:check
             - name: Upload SARIF
               if: always() && steps.filter.outputs.deps == 'true'
               uses: github/codeql-action/upload-sarif@v4
               with:
                 sarif_file: backend/target/dependency-check-report.sarif
                 category: owasp-dependency-check
             - name: Upload HTML report
               if: always() && steps.filter.outputs.deps == 'true'
               uses: actions/upload-artifact@v7
               with:
                 name: owasp-dependency-check-report
                 path: backend/target/dependency-check-report.html
                 retention-days: 14
                 if-no-files-found: ignore
       ```
       Do NOT add this job to the `ci-complete` `needs[]` (matches the `mutation` job's informational-only pattern).

    5. Avoid: do NOT remove the existing Trivy jobs (Trivy scans containers, dep-check scans Java deps — different layers); do NOT make this part of the default `verify` (NVD downloads make it slow); do NOT lower `failBuildOnCVSS` to 7.0 (HIGH) without a separate plan — too many false positives in transitive deps; do NOT pin the plugin version below 9.x (older versions hit a deprecated NVD JSON 1.1 endpoint that is being retired); do NOT set `<failOnError>true</failOnError>` (network failures should not break the build — that is a flake source, the report itself is the gate).

  <name>Task 2: ProductionProfileGuard + CORS env-var binding + tests</name>
  <files>backend/src/main/java/com/fintrack/common/config/ProductionProfileGuard.java, backend/src/main/java/com/fintrack/common/config/SecurityConfig.java, backend/src/main/java/com/fintrack/common/config/CorsProperties.java, backend/src/main/resources/application.yml, backend/src/test/java/com/fintrack/common/config/ProductionProfileGuardTest.java</files>
  <action>
    1. `CorsProperties` — `@ConfigurationProperties(prefix = "fintrack.cors")` record with `List<String> allowedOrigins`. Bind in `application.yml`:
       ```yaml
       fintrack:
         cors:
           allowed-origins: ${CORS_ALLOWED_ORIGINS:}
       ```
       Spring binds the env var as a comma-separated list out of the box for `List<String>`.
    2. `SecurityConfig.corsConfigurationSource()` — replace the hard-coded `List.of("*")` with `corsProperties.allowedOrigins()` when non-empty, falling back to the wildcard `["*"]` ONLY when running outside production (detection: inject `Environment` and check `env.matchesProfiles("!production")`). In production, the guard from Task 2 step 3 will already have failed startup if the list is empty — but defence in depth: when the production guard is bypassed by a test slice, the wildcard fallback must NOT engage, so the actual code path is "use whatever the property holds, no fallback". The dev profile sets `CORS_ALLOWED_ORIGINS=*` in `.env.example` to keep dev workflows unchanged.
    3. `ProductionProfileGuard` — `@Component @Profile("production") @RequiredArgsConstructor`. `@PostConstruct void enforce()` runs once at boot and validates:
       - `CORS_ALLOWED_ORIGINS` is non-empty AND does not contain `*`. Wildcard in prod is forbidden.
       - `SPRING_REDIS_PASSWORD` is non-blank. (Inject `Environment` and read directly; do NOT assume Spring Data Redis would otherwise complain — it accepts blank password silently.)
       - `JWT_SECRET` is non-blank AND not equal to the dev default `dev-secret-change-in-production-must-be-256-bits-long`.
       - `RECEIPT_SIGNING_SECRET` is non-blank AND not equal to the dev default `dev-receipt-signing-secret-change-in-production-must-be-32-bytes`.
       - `WEBAUTHN_RPID` and `WEBAUTHN_ORIGIN` are non-blank (added by plan 24-02; production must point at the real origin).
       Each failure throws `IllegalStateException` with a clear message naming the env var and the remediation. Spring Boot startup fails fast, the container exits non-zero, the operator sees the message in `docker compose logs`. Aggregate all failures into a single `IllegalStateException` (newline-separated) so the operator sees every misconfiguration in one shot rather than one per restart.
    4. `application.yml` production section — append a `production` profile block (if it does not yet exist) at the end of the file:
       ```yaml
       ---
       spring:
         config:
           activate:
             on-profile: production
       ```
       No additional config — the guard handles validation. Existing `application.yml` already has a `development` profile section to mirror.
    5. `ProductionProfileGuardTest` — `@SpringBootTest` with `@ActiveProfiles("production")` and various `@TestPropertySource` overrides:
       - All required env vars set → context loads.
       - Missing `CORS_ALLOWED_ORIGINS` → `ApplicationContextException` whose root cause is `IllegalStateException` mentioning `CORS_ALLOWED_ORIGINS`.
       - Wildcard CORS → similar.
       - Default JWT secret → similar mentioning `JWT_SECRET`.
       - Default receipt secret → similar mentioning `RECEIPT_SIGNING_SECRET`.
       - Multiple failures → message contains every failed key joined by `\n`.
    6. Avoid: do NOT enforce these checks in non-production profiles (developer ergonomics); do NOT silently default to `*` in production (the guard catches this); do NOT validate at request time (boot is the right gate); do NOT couple the guard to the redactor or the worker (scope creep); do NOT remove the dev defaults from `application.yml` (developer onboarding breaks); do NOT use `@EventListener(ApplicationReadyEvent.class)` instead of `@PostConstruct` — `@PostConstruct` runs before the web server starts so a misconfigured prod boot never opens a port.
  </action>
  <verify>
    `cd backend && ./mvnw -B -ntp test -Dtest=ProductionProfileGuardTest` passes.
    `cd backend && ./mvnw -B -ntp verify` succeeds.
    Local: with `SPRING_PROFILES_ACTIVE=production` and no `CORS_ALLOWED_ORIGINS`, `./mvnw spring-boot:run` fails with the multi-line `IllegalStateException` message.
    Local: with all required env vars set in a `.env.production` file, `./mvnw spring-boot:run` boots normally.
  </verify>
  <done>
    Guard enforces all five env-var requirements at boot in production; CORS source no longer hard-codes wildcard; tests cover the pass and at least four failure paths.
  </done>
