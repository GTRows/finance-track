<objective>
Lay the foundation for WebAuthn/passkey sign-in: pick a library, add the `authenticators` child table, wire the relying-party configuration, and ship the registration ceremony (start + finish endpoints) on the backend so an authenticated user can enrol a passkey.

Purpose: Passwords (even Argon2id) remain phishable; passkeys eliminate the shared-secret problem and replace TOTP friction with Touch-ID / Windows Hello / hardware-key flows. This plan stops at registration so the assertion (login) flow and frontend integration get the full attention they need in plan 24-03.
Output: webauthn4j-core dependency wired; Flyway V38 adds `authenticators` table; `Authenticator` entity + repository; `WebAuthnProperties` (rpId, rpName, origin); `WebAuthnRegistrationService` with `startRegistration(userId)` (challenge to Redis with 5-min TTL) and `finishRegistration(userId, body)` (verifies attestation, persists credential); `WebAuthnRegistrationController` exposing `POST /api/v1/auth/webauthn/register/start` and `POST /api/v1/auth/webauthn/register/finish`; tests + OpenAPI regen.
</objective>

<task type="checkpoint:decision" gate="blocking">
  <decision>Pick the WebAuthn library</decision>
  <context>
    Two well-maintained options exist for Java/Spring. The library choice is locked in for the rest of phase 24-02 + 24-03; switching later means rewriting the ceremony layer.
    Both satisfy WebAuthn Level 2; both have active maintenance; both work on Spring Boot 3.2 + Java 21.
  </context>
  <options>
    <option id="webauthn4j">
      <name>com.webauthn4j:webauthn4j-core (latest 0.27.x)</name>
      <pros>
        - Spring-friendly: companion `webauthn4j-spring-security` module exists if we later want filter integration.
        - Smaller surface, idiomatic Java records and Optionals.
        - Active maintenance; tracks WebAuthn Level 3 drafts.
        - Apache 2.0 license.
      </pros>
      <cons>
        - Less battle-tested at extreme scale than the Yubico stack.
        - Some attestation formats (Apple anonymous) trail by a release.
      </cons>
    </option>
    <option id="yubico">
      <name>com.yubico:webauthn-server-core (2.x)</name>
      <pros>
        - Reference implementation maintained by the FIDO sponsor.
        - Strict spec compliance; widest attestation format coverage.
        - Mature, used in production at large IdPs.
      </pros>
      <cons>
        - More opinionated API requires writing more glue code (CredentialRepository SPI to implement).
        - BSD-2 license (still permissive, just different from the rest of the stack).
        - Heavier jar.
      </cons>
    </option>
  </options>
  <resume-signal>Select: webauthn4j or yubico. Default if no input within session: webauthn4j (Spring affinity, smaller surface).</resume-signal>
</task>

  <name>Task 2: Add dependency, Flyway V38 authenticators table, JPA entity + repository</name>
  <files>backend/pom.xml, backend/src/main/resources/db/migration/V38__add_authenticators.sql, backend/src/main/java/com/fintrack/common/entity/Authenticator.java, backend/src/main/java/com/fintrack/auth/webauthn/AuthenticatorRepository.java</files>
  <action>
    1. `backend/pom.xml`: add the chosen library. For webauthn4j: `<dependency><groupId>com.webauthn4j</groupId><artifactId>webauthn4j-core</artifactId><version>0.27.0</version></dependency>` (verify latest stable on Maven Central before pinning; 0.27.x is current as of 2026-04). For yubico: `<dependency><groupId>com.yubico</groupId><artifactId>webauthn-server-core</artifactId><version>2.6.0</version></dependency>`. Add in alphabetical order in the existing dependencies block.
    2. `V38__add_authenticators.sql`:
       ```sql
       CREATE TABLE authenticators (
         id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
         user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
         credential_id   BYTEA NOT NULL UNIQUE,
         public_key_cose BYTEA NOT NULL,
         sign_count      BIGINT NOT NULL DEFAULT 0,
         attestation_fmt VARCHAR(32),
         aaguid          UUID,
         transports      VARCHAR(64),
         name            VARCHAR(64) NOT NULL,
         created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
         last_used_at    TIMESTAMPTZ
       );
       CREATE INDEX idx_authenticators_user_id ON authenticators(user_id);
       ```
       Use `ON DELETE CASCADE` so deleting a user removes their authenticators (matches existing `refresh_tokens` pattern).
    3. `Authenticator` entity in `com.fintrack.common.entity` mirroring the table; `transports` is `VARCHAR` storing CSV (e.g., `"usb,nfc,ble"`) — keep simple, do not introduce JSON columns. Use `@Lob` only if Hibernate complains about BYTEA mapping; otherwise a plain `byte[]` field is enough on PostgreSQL.
    4. `AuthenticatorRepository extends JpaRepository<Authenticator, UUID>` in a NEW package `com.fintrack.auth.webauthn` (sub-package keeps the WebAuthn surface isolated from existing TOTP / refresh-token code). Methods: `List<Authenticator> findByUserIdOrderByCreatedAtDesc(UUID userId)`, `Optional<Authenticator> findByCredentialId(byte[] credentialId)`, `Optional<Authenticator> findByIdAndUserId(UUID id, UUID userId)`, `void deleteByIdAndUserId(UUID id, UUID userId)`.
    5. Avoid: do NOT base64-encode credential_id at the JPA boundary — keep it BYTEA and let DTOs handle encoding; do NOT add a `revoked` boolean (deletion is the revocation model, mirrors `refresh_tokens`); do NOT make `name` nullable (UI requires a label per credential).
  </action>
  <verify>
    `cd backend && ./mvnw -B -ntp spotless:apply compile` succeeds.
    `cd backend && ./mvnw -B -ntp flyway:info` shows V38 pending; `flyway:migrate` succeeds against an empty DB.
    A `@DataJpaTest` smoke test (added in Task 3) round-trips an `Authenticator` row.
  </verify>
  <done>
    Library on classpath; V38 migration created and idempotent against an empty DB; entity + repository compile; package layout `com.fintrack.auth.webauthn` is in place.
  </done>

  <files>backend/src/main/java/com/fintrack/auth/webauthn/WebAuthnProperties.java, backend/src/main/java/com/fintrack/auth/webauthn/WebAuthnRegistrationService.java, backend/src/main/java/com/fintrack/auth/webauthn/WebAuthnRegistrationController.java, backend/src/main/java/com/fintrack/auth/webauthn/dto/RegistrationStartResponse.java, backend/src/main/java/com/fintrack/auth/webauthn/dto/RegistrationFinishRequest.java, backend/src/main/java/com/fintrack/auth/webauthn/dto/RegistrationFinishResponse.java, backend/src/main/java/com/fintrack/audit/AuditAction.java, backend/src/main/resources/application.yml, backend/src/test/java/com/fintrack/auth/webauthn/WebAuthnRegistrationServiceTest.java, backend/src/test/java/com/fintrack/auth/webauthn/AuthenticatorRepositoryDataJpaTest.java</files>
  <action>
    1. `WebAuthnProperties` — `@ConfigurationProperties(prefix = "fintrack.webauthn")` record with `String rpId`, `String rpName`, `String origin`. Bind in `application.yml` under existing `fintrack:` block: `webauthn: { rpId: ${WEBAUTHN_RPID:localhost}, rpName: ${WEBAUTHN_RP_NAME:FinTrack Pro}, origin: ${WEBAUTHN_ORIGIN:http://localhost:5173} }`. Production profile (handled in plan 24-07) will fail-fast if these are blank; for now defaults cover dev.
    2. `WebAuthnRegistrationService` (constructor-inject the chosen library's primary entry point — for webauthn4j that's `WebAuthnManager.createNonStrictWebAuthnManager()` cached as a `@Bean` in a small `WebAuthnConfig`; for yubico it's a `RelyingParty` builder). Methods:
       - `RegistrationStartResponse start(UUID userId)` — load `User`, generate a 32-byte `challenge` via `SecureRandom`, build `PublicKeyCredentialCreationOptions` (rp = (rpId, rpName), user = (userId.toBytes, username, displayName=username), pubKeyCredParams = ES256+RS256, timeout = 60_000, attestation = NONE, residentKey = PREFERRED, userVerification = PREFERRED), serialize the challenge into Redis under key `webauthn:reg:<userId>` with 5-minute TTL via `StringRedisTemplate.opsForValue().set(key, base64url(challenge), Duration.ofMinutes(5))`, return the options (Base64URL-encoded for browser transport).
       - `RegistrationFinishResponse finish(UUID userId, RegistrationFinishRequest body)` — pop the challenge from Redis (atomic via `getAndDelete`), call the chosen library's verifier with (rpId, origin, challenge, body.clientDataJSON, body.attestationObject), on success persist a new `Authenticator` (credential_id, public_key_cose, sign_count = result.signCount, attestation_fmt, aaguid, transports CSV, name = body.name) and return `{id, name}`. On failure throw `BusinessRuleException("Registration failed", "WEBAUTHN_REGISTRATION_INVALID")`.
       - Both methods `@Transactional`. Audit success/failure via `auditService.success(AuditAction.WEBAUTHN_REGISTER_*, userId, username)`.
    3. `WebAuthnRegistrationController` — `@RestController @RequestMapping("/api/v1/auth/webauthn/register") @RequiredArgsConstructor`. `POST /start` (auth required) → `RegistrationStartResponse`. `POST /finish` (auth required) → `RegistrationFinishResponse`. Both bind `@AuthenticationPrincipal FinTrackUserDetails` and pass `user.getId()` into the service. Add the routes to the security chain — they require an authenticated user, NOT the public list.
    4. Add `WEBAUTHN_REGISTER_STARTED`, `WEBAUTHN_REGISTER_COMPLETED`, `WEBAUTHN_REGISTER_FAILED` to `AuditAction`.
    5. DTOs as Java records under `com.fintrack.auth.webauthn.dto`: `RegistrationStartResponse(String challenge, String rpId, String rpName, String userId, String userName, List<PubKeyCredParam> pubKeyCredParams, long timeout, String attestation, String userVerification)`; `RegistrationFinishRequest(@NotBlank String name, @NotBlank String credentialId, @NotBlank String clientDataJSON, @NotBlank String attestationObject, @NotNull List<String> transports)`; `RegistrationFinishResponse(UUID id, String name)`. Use `@Schema` annotations only where springdoc needs help (already on classpath).
    6. Tests:
       - `AuthenticatorRepositoryDataJpaTest` — extends `AbstractDataJpaTestSupport` (pattern from 23-01); seeds a user via the helper, persists an `Authenticator`, asserts `findByUserId`, `findByCredentialId`, `findByIdAndUserId`, and `deleteByIdAndUserId` round-trip correctly.
       - `WebAuthnRegistrationServiceTest` — `@ExtendWith(MockitoExtension.class)`. Mock `UserRepository`, `AuthenticatorRepository`, `StringRedisTemplate` (and `ValueOperations`), `WebAuthnManager` (or yubico equivalent), `AuditService`. Cases: (a) `start(userId)` writes a 32-byte base64url challenge to Redis with 5-min TTL and returns options containing the same challenge; (b) `finish(userId, body)` happy path verifies attestation, persists the Authenticator with the right fields, audits `WEBAUTHN_REGISTER_COMPLETED`; (c) missing/expired Redis challenge → `BusinessRuleException("WEBAUTHN_CHALLENGE_INVALID")`; (d) library returns invalid attestation → `BusinessRuleException("WEBAUTHN_REGISTRATION_INVALID")` and audit failure.
    7. Avoid: do NOT store the challenge in the JPA layer (Redis is the right place; auto-expiry handles cleanup); do NOT skip the `getAndDelete` atomicity — replay protection depends on it; do NOT bind `WebAuthnProperties` via `@Value` (use `@ConfigurationProperties`); do NOT add the new endpoints to `PUBLIC_PATHS` in `SecurityConfig` (registration requires an authenticated user).
  </action>
