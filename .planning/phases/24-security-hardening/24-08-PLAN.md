<objective>
Extend `AuditService` coverage from auth-only events to every domain mutation: create / update / delete on portfolios, holdings, investment transactions, budget entries, categories, bills, and bill payments.

Purpose: CONCERNS.md "Domain mutations not audited" is the largest remaining audit gap. Auth events are well-covered (24-01 through 24-04 added more), but a stolen session today can wipe a portfolio without leaving a trace. Closing this gap is the precondition for the THREAT_MODEL.md residual-risk reduction promised in Phase 24's roadmap line.

</objective>

       - `INVESTMENT_TRANSACTION_CREATED`, `INVESTMENT_TRANSACTION_UPDATED`, `INVESTMENT_TRANSACTION_DELETED`
    2. Open each service file, locate every `@Transactional` method that mutates state (excluding read-only and pure-compute helpers). Inject `AuditService` via the existing `@RequiredArgsConstructor` (Lombok handles it once the field is added). At the end of each successful mutation (after the entity is saved or deleted), emit `auditService.success(AuditAction.PORTFOLIO_CREATED, userId, username, "id=" + portfolio.getId())` using the userId already in scope. The username — these services do NOT carry the username today; load it via `RequestContext` (extend `RequestContext` with a `username()` helper if not present, or load from `SecurityContextHolder.getContext().getAuthentication().getName()`). Prefer the `SecurityContextHolder` route — it is the existing convention used by the JWT filter.
    3. For methods that throw `BusinessRuleException` (e.g., trying to delete a portfolio that holds open positions, or invalid quantity on an investment transaction), wrap the throw site with `auditService.failure(action, userId, username, ex.getMessage())` and rethrow. Do NOT catch unchecked exceptions just to audit — only the business rule branches that the service explicitly raises.
    4. Tests: ONE `*ServiceAuditTest` per service. `@ExtendWith(MockitoExtension.class)`. Mock all repositories + `AuditService`. Each test:
       - Create: invoke the create method, `verify(auditService).success(eq(AuditAction.PORTFOLIO_CREATED), eq(userId), anyString(), contains(portfolio.getId().toString()))`.
       - Update: same shape with `PORTFOLIO_UPDATED`.
       - Delete: same with `PORTFOLIO_DELETED`.
       - Failure path (e.g., delete with open holdings): `verify(auditService).failure(eq(AuditAction.PORTFOLIO_DELETED), eq(userId), anyString(), anyString())`.
       That is 4 cases per service × 3 services = 12 new tests, on top of the existing service tests.
    5. Avoid: do NOT emit audit BEFORE the DB write (a rollback would leave a misleading audit row); do NOT use `@Transactional(REQUIRES_NEW)` here (`AuditService.record` already opens REQUIRES_NEW so the audit row commits independently of the calling transaction); do NOT log the entire entity in the detail (id is enough; the mutation type is in the action); do NOT add audit emission to read-only methods (`get`, `list`); do NOT modify the entity contracts (no entity field changes); do NOT add the audit fields to DTOs (audit is a side effect, not a contract).
  </action>
