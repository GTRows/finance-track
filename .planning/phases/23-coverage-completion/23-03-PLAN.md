<objective>
Add frontend↔backend contract tests so hand-written `frontend/src/api/*.api.ts` modules cannot drift from the Spring REST surface (Track A8).

Purpose: The OpenAPI spec is already produced by springdoc; the frontend types are still hand-written. The risk is silent drift — a controller renames a field, the frontend keeps the old shape, and only a manual smoke test catches it. Generating the canonical type surface from the spec and CI-asserting that hand-written types match closes that loop.

Output: A committed `openapi.json` produced from a booted backend, a generated `frontend/src/api/openapi.types.ts` produced by `openapi-typescript`, a Vitest contract test that imports both the hand-written DTOs and the generated types and fails on shape mismatch, and a CI step that regenerates the spec and fails the build on diff.
</objective>

**Tech stack available:** springdoc-openapi (already producing `/v3/api-docs`), Vite 5, Vitest 1.3, TypeScript 5.4 strict, ESLint zero-warning gate, npm.
**Established patterns:** Hand-written `frontend/src/api/{feature}.api.ts` modules export an object with named methods that thread `client` (axios). Type definitions live in `frontend/src/types/{feature}.types.ts`.
**Constraining decisions:** TypeScript strict, no `any`. Frontend lints with `--max-warnings 0`. Generated code must compile under the same rules.
**Discovery (Level 1):** `openapi-typescript` is the lightest tool that produces idiomatic TS interfaces from an OpenAPI 3 spec — preferred over `openapi-generator-cli` which adds Java/Gradle plumbing the project doesn't need. Pact would solve a different problem (consumer-driven runtime contracts); for static drift detection, schema diff is sufficient.
</context>
