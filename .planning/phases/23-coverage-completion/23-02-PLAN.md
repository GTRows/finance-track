<objective>
Add PIT mutation testing on the service layer with a 60% mutation-score gate (Track A7).

Purpose: Coverage percentages no longer move the needle — the unprotected mutations do. PIT (pitest-maven) replaces lines that have been "tested" with mutations and reports which ones the test suite still catches. A 60% floor on the service layer is realistic for a brownfield project at 77% instruction / 62% branch JaCoCo coverage and surfaces the worst-tested business logic first.

Output: pitest-maven configured in `backend/pom.xml`, a `mutation` Maven profile that runs against the service layer with a 60% kill threshold, an HTML report under `backend/target/pit-reports/`, and a CI workflow step that runs the profile on PRs touching service classes.
</objective>

**Tech stack available:** Maven 3.x via mvnw, JUnit 5 (with Jupiter engine), JaCoCo 0.8.12, GitHub Actions backend job.
**Established patterns:** Maven profiles already used for Spotless and JaCoCo gates; CI runs `./mvnw verify` on push and PRs.
**Constraining decisions:** Mutation testing is slow (5-15 min for a project this size). Do NOT attach it to the default `verify` lifecycle — use a separate profile so day-to-day local builds stay fast.
**Discovery (Level 1):** pitest-maven 1.17.x is current and supports JUnit 5 via the `pitest-junit5-plugin`. Default mutators (`DEFAULTS`) are enough for the first run; consider `STRONGER` only after the first kill score is established.
</context>
