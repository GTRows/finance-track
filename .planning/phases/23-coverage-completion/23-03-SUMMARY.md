## Decisions Made

- **JUnit `@SpringBootTest` over `springdoc-openapi-maven-plugin`.** The plan called for the Maven plugin, but both approaches need to boot the app and the plugin would have required wiring `spring-boot-maven-plugin` start/stop lifecycle hooks plus autoconfig exclusions for DB/Redis to avoid external service dependencies. The test approach reuses Spring Boot's existing test machinery, runs as part of `mvn test` opt-in, and produces the same deterministic spec. Reproducibility (the plan's stated intent) is preserved.
- **Plain `docker run` instead of Testcontainers** for the ephemeral Postgres in `regen-openapi.sh`. Testcontainers' Docker auto-detection on Docker Desktop on Windows hits the user-mode `\\.\pipe\docker_engine` which returns a stub `Info` payload — reproducible failure across multiple discovery strategies. The CLI works (it goes through the desktop-linux context). Using `docker run`/`docker exec` directly removes the dependency on the Java SDK's Docker discovery.
- **`keyof` equality instead of full structural equality** for the contract test. Springdoc emits every field as `?:` absent `@JsonProperty(required = true)`; hand-written types express true presence. Strict equality on the structural type surface would either always pass (after applying `Partial<>` to handwritten) or always fail (against the all-optional generated). `keyof` equality after stripping optionality on the generated side is the strongest signal that does not require modelling either side's optional/null surface.
- **`@Schema(name = "InvestmentTransactionResponse")`** to disambiguate the duplicate `TransactionResponse` simple name. Renaming the file would touch every caller; the annotation is a one-line OpenAPI-only fix.

## Deviations from Plan

### Auto-fixed Issues

The plan assumed the full Spring app could already boot in tests. It cannot on the current branch. The following bugs surfaced and were fixed inline because the plan cannot proceed otherwise:

1. **Bean-name collision on `AllocationController`.** Two `@RestController` classes (`com.fintrack.budget.allocation.AllocationController` and `com.fintrack.portfolio.allocation.AllocationController`) auto-derive the same bean id `allocationController` and conflict at component scan. Fixed by giving each an explicit name via `@RestController("budgetAllocationController")` and `@RestController("portfolioAllocationController")`.
2. **TotpService cannot be instantiated.** Two constructors and no `@Autowired` marker; Spring 6 falls back to the no-arg ctor and fails. Marked the public ctor with `@Autowired`.
3. **Two repository `@Query` methods reference inner-class enum constants** by full name (`com.fintrack.common.entity.PriceAlert.Status.ACTIVE`); Hibernate 6 cannot interpret this path expression. Refactored to parameter binding via default methods so the public repository API is unchanged.
4. **Duplicate `TransactionResponse` DTO names** collide in springdoc's schema namespace. Disambiguated the portfolio one via `@Schema(name = "InvestmentTransactionResponse")`.

These bugs were latent because the project has no full `@SpringBootTest` — only `@DataJpaTest` and `@WebMvcTest` slices that don't trigger the failing code paths. Plan 23-03 is the first time the full context is loaded; running it forced a fix.

### Drift fixes triggered by the contract test

5. **Bill type drift.** Hand-written `Bill.isActive` is the wrong name (BillResponse emits `active`); fixed plus consumers (BillsPage, BillsCalendar). Added `currency`, `autoPay`, `notes` which the response actually returns.
6. **PriceSyncResult drift.** Hand-written type was missing `fundUpdated`, `metalUpdated`, `stockUpdated`. Added them.

### Tooling deviation

7. **JUnit test instead of `springdoc-openapi-maven-plugin`** (see Decisions above).
8. **Plain `docker run` instead of Testcontainers** for the regen script (see Decisions above).

**Total deviations:** 6 latent bug fixes (in-scope unblockers), 2 tooling deviations (justified above)

**Impact on plan:** All success criteria met. Plan widened slightly to include the unblocker fixes; nothing was deferred.

## Issues Encountered

- **Docker Desktop pipe returns malformed `Info`** on Windows. The pipe at `\\.\pipe\docker_engine` responds but with all-zero fields except a single label pointing at `\\.\pipe\docker_cli`. Both `EnvironmentAndSystemPropertyClientProviderStrategy` (with `DOCKER_HOST=npipe:////./pipe/dockerDesktopLinuxEngine`) and `NpipeSocketClientProviderStrategy` (default) hit the same response. The Docker CLI itself works via the `desktop-linux` context. Worked around by orchestrating Postgres directly with `docker run`/`docker exec` from the regen script.
- **`@Query` HQL parses fully-qualified inner-enum** in Hibernate 5 but not Hibernate 6.4. The `findAllActiveWithAsset()` call is reached at every login (price-alert evaluation). The bug would have manifested in production at runtime; the contract gate work surfaced it at boot time.
- **Duplicate DTO class simple names** are easy to introduce in feature-package codebases (`com.fintrack.budget.dto.TransactionResponse` vs. `com.fintrack.portfolio.transaction.dto.TransactionResponse`); springdoc collapses by simple name and emits a single (wrong) schema. Worth a static check or a CI guard to flag duplicates in `dto/` packages.
